# Paper Reading — 论文阅读工作流

科研骨架的论文阅读模块。目标：把一篇论文读深读透，产出**符合自家格式、经得起对抗质疑**的阅读报告。

## 第 0 步：场景判定（先定深度，再选流程）

阅读需求不同，深度和产出完全不同。**先判定场景，再走对应流程**：

| 场景 | 触发 | 深度 | 产出 | 状态 |
|------|------|:--:|------|------|
| A. 搜索 | 找新论文 / 调研方向 | L1 | 候选表 + 入库 | ✅ 本轮 |
| B. 防撞车 | 组会前 related work | L1-L2 | 风险分级对比表 | ✅ 本轮 |
| C. 快速读 | 判断是否值得精读 | L1 | 一句话总结 + 定位 | ✅ 本轮 |
| **D. 精读报告** | 正式阅读 / 写报告 | L2-L3 | **六节模板 + 置信度 frontmatter** | ✅ 本轮 |
| E. 深挖对抗 | 跟进 / 定 PRP 方向 | L3-L4 | 脆弱假设 → 反例 → idea | 后续轮 |
| F. 引用审计 | 投稿 / 引用核实 | — | 每条引用三层验证 | 后续轮 |

> 本轮实现 A（搜索入库）+ B（防撞车）+ C（快速读）+ D（精读）。遇到 E/F 触发词，先确认是否真需要精读；不需要就按浅场景快速处理，不强行走 D。

## D 场景：精读闭环

### D1. 定位与抓原文（不盲信）

1. **定位**：WebSearch 确认 arXiv / DOI / 官方发表信息（会议/年份），优先官方正式版而非 preprint。**代码链接常在论文正文而非 arXiv abs 页**——abs 页查不到不等于不存在，需直接访问 repo/正文核实
2. **抓原文**：**禁止只看摘要**。arXiv HTML 优先（WebFetch 可读全文），PDF 次之；公式/证明/实现细节走 LaTeX（alphaxiv Tier 3）
3. **至少读到**：方法 + 实验 + 结论。**关键数字逐一核对原文**，不转抄二手
4. 微信/媒体文章被反爬 → 搜转载或原文替代

### D2. 六节报告（格式规格，锁定）

按项目根 CLAUDE.md 的「论文阅读模板」写，骨架：

```markdown
# {论文简称} 阅读报告

> **基本信息**: 标题 / 作者 / 会议年份 / DOI / 代码链接(如有)

## 一、核心问题与动机
## 二、方法
## 三、实验与结果
## 四、与 {PRP/实习} 的关系    ← 第四节按项目识别选版本
## 五、局限
## 六、个人体会                 ← 末条含"对 {PRP/实习} 的启发"
```

- **第四节、第六节版本 + 保存路径按项目 CLAUDE.md 项目识别表判定**（PRP → `prp/notes/`；实习 → `Internship/notes/0-cross-cutting/`），禁止混用
- 写作风格：中文为主、术语保留英文；能用表格不用段落；bullet ≤ 3 行；正文无 emoji
- **公式策略按受众定（写前先判受众）**：专业/技术受众 → 保留公式，**用 Obsidian LaTeX**（行内 `$...$`、独立行 `$$...$$`），不用纯文本/Unicode 手写（如 `$r^D_{i,t}=D_{i,t-1}-D_{i,t}$`）；一般组会/进度分享 → 去掉公式、抓核心思想——组会是分享进度的，不是上数学课的
- **六节一个都不能少**。「局限」「个人体会」不许并入其他节（基线反例：早期 prp 报告把两节合并/删除）
- （可选）首行加「一句话总结」——后期报告自发的好实践，非模板必需

### D3. 置信度 frontmatter（强制，必填）

```yaml
---
confidence: 🟢 高        # 🟢高 / 🟡中 / 🟠低 / 🔴极低
verified: arXiv HTML 全文  # 核实方式：全文 / 摘要 / 搜索摘要 / 博客
verified_date: YYYY-MM-DD
notes: 待核实项、已知局限   # 选填
---
```

| 等级 | 含义 | 核实标准 |
|------|------|---------|
| 🟢 高 | 可引用 | 已读全文，关键数字逐一核实 |
| 🟡 中 | 概念可靠，细节待核 | 已读摘要或单一可靠来源 |
| 🟠 低 | 仅工程参考 | 博客/教程汇编，无学术原文 |
| 🔴 极低 | 不可引用 | 新闻/企业自报，无独立验证 |

### D4. 信息卫生（四类信息严格区分）

每条信息先归类再落笔：

| 类别 | 写法 |
|------|------|
| ① 论文声称 | 正文直接写，来源=本论文 |
| ② 文献既有结论 | 写明是 prior work 的结论，非本论文贡献 |
| ③ 基于证据的推断 | 标注"推测/说明"，**不写成像事实** |
| ④ 猜测 | 不入正文，或明确标「⚠️ 待核实」 |

**关键数字至少两个独立来源一致才写为事实**；单来源 → 标「⚠️ 待核实」。原文未提的 → 写「原文未提及」，不推演。

**落地约定**：方法/实验节只写论文声称的事实（①）；推断与建议集中在「个人体会」节，用「可考虑/推测/说明」动词显式标注（③）；不确定项标「⚠️ 待核实」（④）。

### D5. 批判性（承诺式攻击，不和稀泥）

「局限」「个人体会」不写"平衡弱点清单"，借用 ARIS kill-argument 原则——**只挑最强单一批评点深挖**：

- **批判从方法依赖链推导**：每个核心组件依赖什么输入？该依赖在真实流程中真实存在吗？谁提供它？——从具体依赖找瓶颈，不凭空怀疑（例：多模态模型依赖"每子电路的功能摘要"，现实流程谁写摘要？）
- 最脆弱的一环：假设与结论匹配吗？scope 是普遍还是条件性？
- 证据 vs 声称的 gap：论文声称证明了 X，实验实际证明了什么？
- 每个局限深问：这是真局限，还是换了个说法？最坏情况是什么？
- 反例设计：对手会怎么反驳这篇？

### D6. 验证（跨模型，骨架范式）

- **数字一致性**：报告里每个数字 vs 原文逐一核对
- 语义复核（可选）：review.py 以敌手身份攻击报告——"报告哪里歪曲了原文？"
- 图表（可选）：vision.py 读论文图表，核对报告描述
- 完成后跑 md-format-fixer

### D7. 配图嵌入（可选，报告配论文原图）

让报告直接带论文的重要原图（架构/机制/主结果），组会/导师看报告即见图。

**优先级（实测结论）**：
```
① arXiv 源码包（最可靠，首选）—— arxiv_fetch.py source <id> --outdir 笔记/assets/
   下载 e-print → 解压 → \includegraphics 反查作者原图 → PDF 转 PNG
   （作者原始 figure 文件，无碎片/无渲染损耗，矢量保持矢量）
② 区域渲染（回退，仅当无源码/源码乱）—— office_tools extract pdf --outdir
   （extract_image 原始字节会拿复合图碎片，已踩坑，弃用）
```

1. **取图**：优先 `source` 拿作者原图；无源码才用 `extract`
2. **精选**：`office_tools classify <assets>/`（vision 分价值/装饰）；挑 **1-4 张有信息量**的原图（架构/机制/主结果），跳过装饰
3. **嵌入**：在报告对应章节加
   ```
   ![图：<一句话准确说明（vision 读后写）>](assets/xxx.png)
   ```
4. **原则**：只放有信息量的原图，1-4 张为宜不堆图；图说明用 vision 描述写准确，不猜

## A 场景：搜索与入库（信源收集）

论文库是跨场景的基础设施——B 防撞车从库里取候选，D 精读用库定位。**找新论文/调研/收集信源先走 A**。

### A1. 工具
- **`papers/arxiv_fetch.py`**（项目根统一论文库）：多信源搜索（arxiv/dblp/openalex，semantic 可选）+ 结构化元数据 + PDF 下载 + 引用数 + BibTeX + 状态机 + 人读视图
- **OpenAlex**：稳定无 key，venue/year/存在性权威元数据；**引用数对近期论文滞后**（2025-2026 多显示 0）——`cite` 用它做底 + S2 兜底补当前数
- **WebSearch**：泛发现、行业、中文、政策信源（WebSearch 给不了结构化元数据/PDF，由脚本补）
- **PubMed**（`pubmed` 子命令）：实习线临床证据源——失能评估/ADL/衰弱/长护医学文献，esearch+esummary 免费无 key；`--save` 追加 markdown 表到笔记
- **S2_API_KEY**（可选）：Semantic Scholar 无认证间歇可用（个人 key 申请常被拒），有 key 更稳

### A2. 用法速查
```
python papers/arxiv_fetch.py search "all:LLM AND all:logic synthesis" --max 10 [--since 2026-01] --sources arxiv,dblp,semantic [--add] [--relevance 中]
python papers/arxiv_fetch.py add 2505.02168 [--relevance 高]
python papers/arxiv_fetch.py download 2505.02168
python papers/arxiv_fetch.py cite 2505.02168      # Semantic Scholar 引用数（写回索引）
python papers/arxiv_fetch.py bibtex 2505.02168    # DBLP 权威 BibTeX（写回 dblp_key）
python papers/arxiv_fetch.py pubmed "gait speed frailty older adults" --max 10 [--save 笔记.md]   # 实习线临床证据
python papers/arxiv_fetch.py status 2505.02168 read
python papers/arxiv_fetch.py relevance 2505.02168 高
python papers/arxiv_fetch.py view     # 重建 library.md 人读视图
```
脚本 `__file__` 相对定位（机器无关）；PDF 存 `papers/pdf/`，索引 `papers/index.jsonl`。

### A3. 工作流
1. **拆词**：需求拆成 arXiv 查询（靶心维度 / 方向关键词）
2. **多源搜索**：arxiv_fetch.py search + WebSearch（行业/中文/政策）交叉
3. **去重合并**：以 arXiv ID 为主键（脚本自动）
4. **过滤**：时间窗（--since）、venue、领域
5. **相关度标**（高/中/低）+ 入库（status=candidate）
6. **下载 PDF**（需要精读时）
7. **状态流转**（见 A4）

### A4. 状态机
`candidate`（发现）→ `fetched`（已下 PDF）→ `read`（已精读）→ `report`（已写报告）→ `cited`（已引用） | `rejected`（不相关）
> 写完阅读报告记得 `status <id> report`，库就能反映「哪些读了哪些没读」。

### A5. 与 B/D 衔接
- **B 防撞车**：search --add 入库 → 从库取候选分级（B3 搜索可直接用脚本）
- **D 精读**：add 定位 → D1 抓全文 → 写报告后 `status <id> report`

### A6. 边界
- 摘要级判定 ≠ 全文确认（同 B6）
- 信源缺一个不影响（graceful degradation）
- 论文库本地 git 留痕（`papers/` 独立 repo，**不 push**）；`.gitignore` 排除 `pdf/`（可重下）；脚本无 key、无绝对路径，可复用

## B 场景：防撞车检查（组会前 related work）

组会前/投稿前检查「有没有人做了我们做的事」。深度 L1-L2（摘要+扫读），产出风险分级对比表。

### B1. 定靶心
先明确「要防什么撞」——列出本项目的**核心组合维度**（例：LLM agent + 在线 ABC + GNN 编码 + GRPO）。靶心是比对基准，越具体越好。

### B2. 定范围
相关会议（DAC/ICCAD/ICLR/ICML/NeurIPS/ASP-DAC 等）+ 时间窗（近 1-2 年）+ arXiv 预印本；注明检索日期。

### B3. 多源搜索
按靶心拆关键词组，多轮搜（WebSearch + arXiv + Semantic Scholar）。**顺带扫行业/厂商动向**（如 Synopsys/Siemens 的 agentic EDA——商业系统不撞车，但印证方向、进「需警惕信号」）。每篇新论文回答三问：
- 做了什么？
- 和靶心重叠哪些维度？
- 差异在哪（任务 / 方法 / 数据 / 目标）？

### B4. 按风险分级

| 等级 | 判定 | 处置 |
|------|------|------|
| **高 ⚠️ 直接撞车** | 同一任务 + 同一方法组合 | 立即升 D 精读确认，重定差异化 |
| **中 🔶 范式相近** | 同任务不同方法，或同方法不同任务 | 组会前升 D 精读，盯紧 |
| **低 ✅ 部分重叠** | 仅单维度重叠 | 记录即可 |

> 核心判定：**任务 × 方法维度的组合**是否被同一篇覆盖——不是「提到类似词」就算撞，全部维度勾上才是直接撞车（反例：有人用 GRPO 但做的是标准单元版图，不是逻辑综合 → 不撞）。

> **时间线边界（deadline 分水岭）**：判撞车先定时点基准 = **本项目目标投稿的 submission deadline**（不是录用/发表）——审稿人可见范围 = 投稿时点 + 审稿期间已公开的工作。
> - 对方公开日 < 本项目 deadline → **审稿可见** → 按风险等级处理（高/中必须差异化）
> - 对方公开日 > 本项目 deadline → **审稿不可见** → 不撞（但记录；camera-ready 前公开则补一句对比）
> - 灰色带（deadline 前后数周）→ 保守当可见处理

### B5. 产出（模板）
1. **风险分级表**：论文 | 时间 | 做了什么 | 和我们的差异
2. **全景矩阵**：靶心维度 × 每篇打勾——一眼看出谁最接近
3. **关键发现**：趋势（如「GRPO 正快速进入 EDA」）
4. **需警惕的信号**：活跃组、快速进入的领域、投稿时间线竞争
5. **建议**：组会前该精读哪篇（升 D）、该持续关注哪些新出论文

### B6. 边界
- **摘要级判定 ≠ 全文确认**——中/高风险务必升 D 精读再下结论
- 结论写「无直接撞车」要基于维度矩阵，不是凭印象
- 遵循 D4 信息卫生：论文声称 vs 我们的推断分开标注
- **相似但不互相影响的条件**（满足任一，即便内容大量相似也不构成撞车）：① 对方 deadline 后公开且独立发展（concurrent）② 贡献点不重叠（模式/层次/评估对象不同——如离线压缩算子 vs 在线选算子）③ 上下游互补（你的输入是对方输出）

## C 场景：快速读（判断值不值得精读）

拿到一篇候选（A 搜索 / 防撞车 / 推荐 / 微信），不确定要不要精读。**过滤器**——几分钟判完，省下精读时间。

**深度 L1**：只读摘要 + 标题 + 作者/机构/年份 + 引言末段/贡献列表 + 扫图。**不读全文细节**。

**产出**：一句话总结 + 定位 + 处置建议（升 D / 入库 / 放弃）。紧凑速记，不写完整报告。

### C1. 抓摘要
- arXiv 论文：`papers/arxiv_fetch.py add <id>` 已存 abstract（或 `list` 看库里），或 WebFetch abs 页
- 无 arXiv（期刊/会议/微信转载）：WebFetch 摘要页 / 论文首页
- 先建立第一印象：标题 / 作者 / 机构 / 年份 / venue

### C2. 五问定位（几分钟内答完）
1. 做什么？（任务）
2. 怎么做？（方法一句话）
3. 结果如何？（关键数字/结论）
4. 和我们什么关系？（相关度 高/中/低 + 对应哪个项目线/场景）
5. 值不值得精读？（见 C4）

### C3. 一句话总结
格式：**「用 X 方法做了 Y 任务，关键结果是 Z」**——压缩到一句话，让人 5 秒内懂这篇干了什么。不用完整六节。

### C4. 处置三选一
| 处置 | 条件 | 动作 |
|------|------|------|
| **升 D 精读** | 高相关 + 可能是范式/方法/竞争 | 走 D 场景完整报告 |
| **入库候选** | 中相关，可能后续用 | `add <id> --relevance 中`，状态 candidate |
| **放弃** | 低相关 / 明显不搭 | 不入库，或标 rejected |

### C5. 边界
- 摘要 ≠ 全文——「值得精读」不等于「搞清楚了」，升 D 后仍要读全文
- **防撞车中/高风险候选必须升 D**，不能停在 C
- 「结果如何」只记关键数字，不核对细节（核对是 D 的事）
